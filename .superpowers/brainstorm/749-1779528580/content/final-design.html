Architecture

Self-contained group components
Each component has ProjectID + group fields + Upload. Each independently PATCHes its module's DB row. No aggregator/sink component.
Base class reused as-is
SelvagenModuleComponentBase unchanged. Each new component overrides ModuleTable + CollectValues with its group's subset of fields.
Properties = standalone + dropdown
One Properties component with a module dropdown selector (Topography/Geology/Analyses/Optimizations) + JSON input. PATCHes the jsonb column.
Duplicated groups stay separate
Anl Access ≠ Opt Access (separate classes, same fields). Noted for future merge when Data Dictionary is built.

Icon Design Guidelines

Per David Rutten's recommendations (ieatbugsforbreakfast.com/2012/07/12/on-icons/)

Module family cohesion
  • All Topography icons share a visual theme (e.g., terrain silhouette base)
  • Small meaningful difference per group (contour lines, slope angle, water drop...)
  • Same approach for Geology, Analyses, Optimizations families
Rutten's rules
  • 2 colors max per icon
  • Dark grey outlines, not black
  • Distinguishable in peripheral vision
  • Functional cues, not feature descriptions
  • Pixel-grid aligned, no near-vertical/horizontal lines

GH_Exposure

Sub-components use GH_Exposure.secondary to avoid cluttering the default component palette. Users find them via the ribbon group or search.

Breaking Changes & Migration

The 4 old mega-components are deleted. This is a breaking change — any .gh file using them will show "missing component" errors. Mitigation: the sample .gh doesn't use them, and the PLUGIN_GUIDE.md will be updated with the new component names and migration notes.

Noted for Future

When built, it would: (1) eliminate hardcoded string literals across all components, (2) enable merging duplicated groups (Anl Access = Opt Access), (3) potentially allow runtime schema discovery from Supabase. Deferred to a follow-up initiative.
